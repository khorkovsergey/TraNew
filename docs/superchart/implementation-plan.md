# Superchart — implementation plan

Nine phases, each ending in something a person can open and judge. After every
phase: typecheck, lint, tests, production build — fixed before the next starts,
as §32 requires.

Sizes are honest. This is weeks of work, and the plan says which parts are the
long ones rather than distributing the difficulty evenly to look tidy.

## Phase 1 — Shell, route, adapter *(medium)*

The frame, with a chart that draws real bars and nothing else.

- `/supercharts` becomes the workspace. The design targets this route; keeping
  it means every existing link, the menu entry and the sitemap stay correct.
- Zones from the design at their stated geometry: global header 44, chart header
  54, tool rail 52, stage, right panel 412 (drag 320–720), dock 264 (160–560).
- `ChartEngineAdapter` — the full interface from §2, and a canvas implementation
  covering `initialize`, `setBars`, `setInterval`, `setChartType`, crosshair and
  visible range. Indicators, drawings and highlights throw `not_implemented`
  until their phase, rather than existing as empty methods that appear to work.
- Focus mode, panel resize and persistence of both.

**Done when:** the route renders the design's frame at 1440, candles draw from
fixture bars, the crosshair tracks without a React render, and panels resize and
remember.

## Phase 2 — Data *(medium)*

- `MarketDataAdapter` per §5.
- **Demo adapter** generating deterministic OHLCV for every interval, labelled
  demo in the connection pill, the legend and any Voyager answer that uses it.
- Twelve Data adapter for daily bars — real, delayed, and marked as such. It has
  no intraday and no volume; the adapter says so rather than filling gaps.
- Symbol search and resolution, interval switching, chart types (candles, bars,
  line, area, baseline, hollow, Heikin Ashi), the volume pane.
- Pagination, out-of-order updates, duplicate bars, cancellation of superseded
  requests, a bar cache keyed by symbol + interval + range.

**Done when:** a symbol can be chosen and every interval and chart type renders;
5,000 bars pan and zoom smoothly; the data status is never ambiguous.

## Phase 3 — Indicators, drawings, Object Tree, Data Window *(large)*

- Indicators from `IndicatorDefinition`, wrapping the existing studies registry
  and adding ATR, VWAP, Stochastic, volume MA and the volume-anomaly study.
- Drawing engine: geometry, hit-testing, handles, snapping, the eleven tools of
  §19. This is the largest single piece in the plan — hit-testing is the part
  canvas does not give away.
- Object Tree and Data Window, both driven by the same state as the chart.

**Done when:** a drawing can be created, selected, moved, styled, locked, hidden
and deleted; the Object Tree matches the chart; the Data Window follows the
crosshair.

## Phase 4 — Layouts, persistence, undo/redo *(medium)*

- `ChartLayout` with `schemaVersion` and a migration path.
- `chart_layout` table, ownership checked server-side; localStorage for guests.
- Transaction-based undo/redo: one Voyager request is one undo.

**Done when:** a layout survives a reload and a device change; undo reverses a
multi-command change in one step.

## Phase 5 — Voyager panel and context *(medium)*

- The panel states and components of §12, inside the existing widget's patterns.
- `VoyagerContextService` with the compression of §9 — summary statistics,
  extremes, anomalies, sampling, last N bars, the selection. Not thousands of
  candles.
- Context chips the person can remove, which changes what is sent.
- Streaming answers with chart references, and two-way highlight on hover.

**Done when:** an explanation names numbered zones, hovering either side
highlights the other, and removing a chip demonstrably changes the answer.

## Phase 6 — Command bus, preview, apply *(medium)*

- `ChartCommand` union, Zod schemas, the `proposed → validated → previewed →
  confirmed → applied → logged` lifecycle.
- Preview layer: dashed, Voyager-marked, never written to the saved layout.
- Action plan, Before/After, diff rows, Apply / Apply selected / Edit / Cancel.
- Voyager Activity log with undo where the action is reversible.

**Done when:** F2 from the design runs end to end and Undo puts it back.

## Phase 7 — Script Lab *(medium)*

Documents, versions, diagnostics, autosave, AI generation and edit, diff,
export. Pine v6 generation reuses the existing templates.

**Done when:** a script generated by Voyager is saved, versioned, exported, and
its history compared.

## Phase 8 — Restricted preview runtime *(large)*

Tokenizer, parser, AST, validator, and an interpreter in a Web Worker with
time, memory and operation limits. The subset of §16 and nothing else; anything
outside it returns the named diagnostic and the required sentence about export.

**No `eval`, no `new Function`.** If this phase overruns, the fallback in §16
applies: ship the TradingNew Indicator DSL first and treat Pine as an export
format — the architecture already allows it.

**Done when:** the subset previews on the chart and unsupported code explains
itself.

## Phase 9 — Responsive, accessibility, analytics, tests *(medium)*

Tablet drawer, mobile bottom sheets and tab bar, keyboard map, the accessible
parallel representation the canvas needs, the analytics events of §27, and the
E2E script of §28.

## Decisions taken in this plan

| Decision | Why | Reversible? |
|---|---|---|
| Canvas, hand-written, behind the adapter | The standing "no chart libraries" instruction plus §24's 5,000-bar target. SVG cannot do the second. | Yes — the adapter is the seam |
| Keep `/supercharts` | The design targets it; every existing link stays correct | — |
| Zod, at the command bus only | §7 permits it; seventeen command types with nested payloads is past hand-writing | Yes |
| Bars outside React state | The crosshair fires on every pointer move | No — architectural |
| Demo data labelled everywhere | The provider has no intraday and no volume | — |
| Strategy Tester marked *Coming next* | §17 forbids a fictional backtest, and there is no strategy runtime | — |

## What is explicitly not in this plan

Realtime streaming (there is no socket transport and no realtime provider), a
strategy runtime, dark theme, and multi-chart layouts. Each is a phase of its
own and none is in the Definition of Done.

## Feature flags

`superchart.enabled`, `superchart.voyager.enabled`, `superchart.scriptLab.enabled`,
`superchart.pinePreview.enabled`, `superchart.strategyTester.enabled`,
`superchart.realtime.enabled` — every one defaulting off until its phase lands,
so a half-built surface is never reachable by accident.
